# Garage

S3-compatible object storage service for the Rekwai application.

## Overview

Garage is a lightweight, self-hosted S3-compatible object storage system designed for geo-distributed deployments. 
It provides the same S3 API compatibility as MinIO but with a friendlier posture to the opensource community.

## Configuration

Garage is configured through TOML files and environment variables:

### Main Configuration (`garage.toml`)

Located at `garage/garage.toml`, this file configures:
- Data and metadata directories
- S3 API region and ports
- Database engine (SQLite for development)
- Replication factor

### Initialization Configuration (`garage-init.toml`)

Located at `garage/garage-init.toml`, used by the initialization container to bootstrap the cluster.

### Environment Variables

Garage allows to configure secrets as environment variables, which is what is preferred here. It requires 
`GARAGE_RPC_SECRET`, `GARAGE_ADMIN_TOKEN` and `GARAGE_METRICS_TOKEN`. Next to that, an access key with a 
corresponding secret key is also required, which are imported into Garage through the `init.sh` script (the script 
consumes `S3_ACCESS_KEY_ID` and `S3_SECRET_ACCESS_KEY`, and is executed by default when running `docker compose up` 
in the project root).

The secret values have specific needs and are documented below. They can easily be generated by running `bash 
generate-garage-secrets.sh`, which uses openssl to generate random data. An example output of this script:

Configure these in your `.env` file:

```bash
# S3 API Configuration
S3_URL=garage                                      # Service name in docker-compose
S3_PORT=3900                                       # S3 API port
S3_ACCESS_KEY_ID=insert-access-key-here            # Must start with GK trailing 24-byte hex-encoded random string
S3_SECRET_ACCESS_KEY=insert-secret-access-key-here # 32-byte hex-encoded random string
S3_REGION=ca-central-1                             # Must match garage.toml s3_region

# Garage Internal Configuration
GARAGE_RPC_SECRET=insert-garage-rpc-secret-here    # 32-byte hex-encoded random string
GARAGE_ADMIN_TOKEN=insert-admin-token-here         # Random token
GARAGE_METRICS_TOKEN=insert-metrics-token-here     # Random token

# Initial Bucket
INITIAL_BUCKET_NAME=upload-documents               # Default bucket created on startup
```

## Running with Docker Compose

Garage is automatically started as part of the main application:

```bash
# Start all services including Garage
docker compose up

# Start only Garage services
docker compose up garage garage-init -d
```

### Service Architecture

The setup includes two containers:

1. **garage**: Main Garage server
   - Provides S3 API on port 3900
   - Stores data in `garage/data/`
   - Uses configuration from `garage/garage.toml`

2. **garage-init**: Initialization container
   - Runs `garage/init.sh` to bootstrap the cluster
   - Creates initial bucket if `INITIAL_BUCKET_NAME` is set
   - Imports predefined S3 credentials
   - Exits after successful initialization

## Connectiong with AWS CLI

AWS CLI can be used to connect to garage. In order to use the AWS CLI with the Garage configuration documented in 
this project, configure AWS CLI like instructed below (this assumes you have AWS CLI installed)

1. Add a profile in `~/.aws/config`:

```
[profile garage]
region = ca-central-1
endpoint_url = http://localhost:3900
```

2. Add the credentials in ~/.aws/credentials`:

```
[garage]
aws_access_key_id=insert-access-key-here
aws_secret_access_key=insert-secret-access-key-here
```

After that, one should be able to use AWS CLI to interact with Garage: `aws s3 --profile garage ls 
upload-documents/`.

## Administration

To run Garage CLI commands, use the garage container:

```bash
# Check cluster status
docker exec garage /garage/garage status

# List buckets
docker exec garage /garage/garage bucket list

# List keys
docker exec garage /garage/garage key list

# Get bucket info
docker exec garage /garage/garage bucket info upload-documents
```

## Data Persistence

Garage data is stored in the `garage/data/` directory:
- `garage/data/meta/`: Metadata (cluster info, buckets, keys)
- `garage/data/data/`: Object data

This directory is mounted as a volume in docker-compose, ensuring data persists across container restarts.

## Troubleshooting

### Garage not starting

1. Check that ports 3900-3904 are not in use
2. Verify `.env` file has correct configuration
3. Ensure `GARAGE_RPC_SECRET` is properly set (32-byte hex string)

### Initialization fails

1. Wait a few seconds for Garage to fully start before init runs
2. Check logs: `docker compose logs garage garage-init`
3. Verify `S3_ACCESS_KEY_ID` starts with "GK" followed by 16 hex characters

### Cannot access S3 API

1. Verify Garage is running: `docker compose ps`
2. Check S3 credentials match between `.env` and application config
3. Ensure `S3_REGION` in `.env` matches `s3_region` in `garage.toml`
